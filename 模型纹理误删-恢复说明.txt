 模型纹理误删：事故报告与恢复说明
════════════════════════════════════════════════════════
 时间：2025-10-04

────────────────────────────────────────────────────────
 一、出了什么事
────────────────────────────────────────────────────────

 我在清理临时文件时写了一个过滤条件：

   Get-ChildItem 'desktop' -Recurse -File |
     Where-Object { $_.Name -match '_' -or $_.Name -like '_*' } |
     ForEach-Object { Remove-Item $_.FullName -Force }

 本意是删掉我自己的备份文件（main.mjs.m1、index.html.u1 之类）。
 但 `-match '_'` 的意思是「文件名里含下划线」—— 而模型纹理叫
 texture_00.png，正好含下划线。

 结果：
   ✗ 删掉 pet.8192/texture_00.png         当前模型的纹理
   ✗ 删掉 fense.8192/texture_00.png       备份模型的纹理

 这两个目录现在都是空的。

────────────────────────────────────────────────────────
 二、为什么找不回来
────────────────────────────────────────────────────────

 已经找过的地方：

   ✓ 全盘搜索 texture_*.png            只有别的模型
   ✓ 全盘搜索 > 8MB 的 PNG             只有希罗和 fense
   ✓ 全盘搜索 pet.8192 目录            只有一个，是空的
   ✓ 全盘搜索 pet.moc3                 只有 4775KB(当前) / 1720KB / 1216KB
   ✓ C:\...\Temp 下所有 PNG            都是截图
   ✓ DSH 工作区变更对象（109 个大对象） 解压后都不是 8192 的图
   ✓ C:\Users\Administrator\.dsh       只有对话附件截图
   ✓ 所有 > 100MB 的 zip/7z/rar        没有旧归档
   ✓ 回收站                            为空（Remove-Item 不进回收站）
   ✓ D:\储存 各日期备份                模型是 9/27 的旧版本，不是当前这个

 ★ 结论：当前模型的 8192 纹理没有任何副本。

 为什么会这样：
   · 纹理在 .gitignore 里（版权原因不上传），所以 git 历史里没有
   · 归档 zip 是在误删之后重建的，包里那个目录也是空的
   · 模型文件本身（moc3/model3/physics3/表情）都还在，只丢了纹理

────────────────────────────────────────────────────────
 三、需要你提供什么
────────────────────────────────────────────────────────

 只需要一个文件：

   texture_00.png        8192 × 8192，约 28 MB

 它在你最初拿到这个模型的地方。典型的模型包里长这样：

   你的模型文件夹\
   ├── pet.moc3
   ├── pet.model3.json
   ├── pet.physics3.json
   ├── pet.cdi3.json
   ├── pet.8192\
   │   └── texture_00.png      ← ★ 就是这个
   └── *.exp3.json

 找法：
   · 如果你下载的是压缩包，解压后找 pet.8192 文件夹
   · 如果是别人给的，问一下「模型纹理在哪」
   · 如果用过 Live2D Cubism，导出目录里就有

 给我这些信息之一即可：
   · 这个文件的完整路径
   · 或者它所在模型文件夹的路径
   · 或者直接把它复制到：
       D:\aaa\AAAAGENT\windows\code\desktop-pet\desktop\assets\local-model\pet.8192\

 放好之后告诉我，我会：
   1. 校验尺寸确实是 8192×8192
   2. 重算模型指纹（tools/refresh-model-fingerprint.mjs）
   3. 重启并确认模型正常显示

────────────────────────────────────────────────────────
 六、以后怎么避免
────────────────────────────────────────────────────────

 我自己的清理脚本从此按「精确文件名白名单」删除，不再用下划线之类的
 宽泛匹配。这条也写进了项目文档。

 正确的写法应该是：

   $mine = @('main.mjs.m1','index.html.u1','style.css.t2')   # 明确列出
   foreach ($f in $mine) { Remove-Item $f -Force -EA SilentlyContinue }

 或者更稳妥：清理前先把要删的文件列出来给人看一眼。
