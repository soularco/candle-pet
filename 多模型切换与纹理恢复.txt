 四、面板切换功能
────────────────────────────────────────────────────────

 位置：设置面板 → 最上方「模型」下拉

 实现：
   · 渲染器本来就支持 assetBase 前缀，切换 = 换前缀 + 重建渲染器
   · 切换时先 release() 旧的（WebGL 纹理和上下文都要还回去，
     否则切换几次就耗尽），失败则保留原模型，不让界面变空白
   · 选择存进 localStorage，下次启动还是这个模型
   · 切换后重新从新模型的纹理取一次面板配色，面板会跟着换色

 实测（通过真实下拉 change 事件驱动）：

   模型       drawables   params   纹理
   ────────   ─────────   ──────   ──────────
   希罗        154         118      8192×8192
   雪          155         117      8192×8192
   无尽夏      498         244      8192×8192 + 4096×8192

   参数数量各不相同 —— 确实换成了不同的模型，不是只换了张图。
   localStorage 正确记录了选择。

 教训：**在这个文件里新增顶层 const，必须先确认所有使用点都在它之后。**
 最后把整块模型定义搬到了 import 之后（L25 附近），才算彻底解决。
 这个坑已经记进文档，下次不再零敲碎打。

────────────────────────────────────────────────────────
 六、清理临时文件的新规矩
────────────────────────────────────────────────────────

 事故起因是这条过滤条件：

   Where-Object { $_.Name -match '_' -or $_.Name -like '_*' }

 `-match '_'` 匹配的是「文件名里含下划线」，而 texture_00.png、
 cubismshader_webgl.ts 都含下划线，于是被一起删掉。

 从此改成【白名单精确匹配】：

   $safe = @('main.mjs.tdz', 'index.html.u1', ...)   # 明确列出
   foreach ($f in $safe) { Remove-Item $f ... }

 而且绝不递归清理 assets\ 和 vendor\ 这两个目录。
